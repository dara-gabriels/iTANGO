# mobile/itango/store-assets/STORE_SUBMISSION_SETUP.md

## Honest framing

Everything in `android/fastlane/` and `ios/fastlane/` **automates** store
submission once the prerequisites below exist. None of those prerequisites
can be created by this build pass — they require real developer accounts,
real payments to Apple/Google, and identity verification tied to your
business. This document is the checklist; you (or whoever holds the
Apple/Google developer accounts) has to walk through it once.

## Android (Google Play)

1. **Google Play Console account** ($25 one-time) — register as "iTANGO" or your registered business entity.
2. **Create the app listing**: package name `app.itango.mobile` (must match `android/app/build.gradle`'s `applicationId` exactly — Fastlane's Appfile already assumes this value).
3. **Generate an upload keystore** (if not already done for `mobile-release.yml`'s Android build step):
   ```bash
   keytool -genkey -v -keystore itango-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias itango
   ```
   Store this file and its password in a password manager — **losing it means you can never update the app under the same listing again.** This is the single highest-stakes secret in the entire mobile release pipeline.
4. **Create a Play Console service account** (Setup → API access → Create new service account), grant it Release Manager permissions, download its JSON key. This is `PLAY_STORE_JSON_KEY_PATH` in the Fastfile.
5. **Complete the Play Console content rating questionnaire and Data Safety form** — required before any release, and the Data Safety form specifically needs to accurately reflect what iTANGO collects (location, contacts if applicable, payment info handled by PSP not stored directly, etc.) per the schema in `database/migrations/`.

## iOS (Apple App Store)

1. **Apple Developer Program account** ($99/year) — enrolled as an organization, not an individual, if "iTANGO" is meant to be the visible seller name.
2. **App Store Connect**: create the app record with bundle ID `app.itango.mobile` (must match `ios/Runner.xcodeproj`'s bundle identifier).
3. **App Store Connect API Key** (Users and Access → Keys → Generate API Key, App Manager role) — this is `APP_STORE_CONNECT_API_KEY_PATH` in the Fastfile, and lets Fastlane upload builds without your personal Apple ID password.
4. **Set up `fastlane match`**: create a **private** Git repository to hold encrypted certificates, then run `fastlane match init` once locally (not in CI) to generate the initial distribution certificate and provisioning profile. `MATCH_GIT_URL` in the Fastfile points at this repo.
5. **App Privacy details** (App Store Connect → App Privacy) — same accuracy requirement as Android's Data Safety form: must reflect the real schema (location, contact/friend-graph data, payment handling via Paystack/Flutterwave, not stored card numbers).

## Store listing content (both platforms)

Neither Fastlane config nor this build pass can write your actual App
Store/Play Store listing copy for you in a way that's honest about a
product that doesn't exist yet in the App Store — but the structural
content needed is:

| Asset | Status |
|---|---|
| App name, subtitle, short/long description | **Draft below** — refine before submitting |
| App icon (all required sizes) | Derivable from the real `iTango_logo.png` provided earlier in this build — needs actual image export at each required resolution (1024x1024 for App Store, adaptive icon set for Play), not generated by this text-based build pass |
| Screenshots (per device size) | Needs real screenshots taken from a running build — cannot be generated without executing the actual app |
| Privacy policy URL | **Must exist before submission on both platforms.** Not drafted here — this needs legal review given real user data (location, payments, messaging) is collected; a placeholder privacy policy is worse than none, since it creates false compliance confidence. |

## What to do once the above exists

```bash
cd mobile/itango/android && bundle exec fastlane android internal
cd mobile/itango/ios && bundle exec fastlane ios beta
```

Then wire `PLAY_STORE_JSON_KEY_PATH`, `APP_STORE_CONNECT_API_KEY_PATH`,
`MATCH_GIT_URL`, and the Android keystore secrets into GitHub Actions
secrets so `.github/workflows/mobile-release.yml` can run these lanes
automatically on release tags instead of manually from a developer machine.

## GitHub Actions secrets checklist

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -i itango-release.jks` output |
| `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | From keystore generation step above |
| `PLAY_STORE_JSON_KEY` | `base64 -i play-store-service-account.json` output |
| `APP_STORE_CONNECT_API_KEY_BASE64` | `base64 -i AuthKey_XXXXXXXXXX.p8` output |
| `MATCH_GIT_URL` | SSH or HTTPS URL of the private certs repo |
| `MATCH_PASSWORD` | The passphrase chosen when running `fastlane match init` |

All of these are consumed by `.github/workflows/mobile-release.yml` — once
set, pushing a `v*` tag builds and uploads to both stores' internal/beta
tracks automatically. Promoting to public production release remains a
separate, manual `fastlane` command on both platforms.
